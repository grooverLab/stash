Why stash holds up

Small guarantees, kept everywhere.

🔗

Symlinks, never copies

The warehouse points at the real skill repos. git pull once - every project sees the update. Nothing drifts.

🎛️

Three pickers, one engine

TUI, browser page, or plain CLI - all converge on the same diff: add checked, remove unchecked, never touch a real file.

🎯

Every skill keeps its description

Claude Code truncates skill descriptions past its listing budget - so every install makes Claude a little more blind, and name-only skills barely auto-trigger. A lean list keeps every loaded skill fully visible.

🪶

Zero dependencies

bash + zsh + BSD nc. No python, no node, no server. The browser picker is a generated file and a one-shot listener.

🛡️

Guard rails

Refuses to run from $HOME, never nests claude-in-claude, never overwrites an existing skill, removes only its own links.

📦

Your data survives

./uninstall.sh removes two symlinks. Profiles, selections, and state stay yours.

🔍

Auditable

Every code path is charted, including open findings, in the source itself. No magic.

FAQ

Short answers to the questions people actually search.

How do I stop Claude Code loading all my skills?

Move them out of the global ~/.claude/skills/ directory into stash's profiles, then select per project with skills-profile pick. Only the global dir and the project's .claude/skills/ load into a session.

Can I disable Claude Code skills for just one project?

Yes - that is the whole point. Selection lives in the project's .claude/skills/ as symlinks; uncheck a profile or a single skill and it stops loading there, while other projects keep it.

Why do some of my skills show name-only, with no description?

Claude Code caps the skill listing at a token budget (about 1% of context). Past it, descriptions are truncated to fit - and name-only skills barely auto-trigger. A leaner per-project list keeps every loaded skill fully described.

Does stash work with plugin skills?

Plugins are managed by Claude Code's own plugin system and keep auto-updating; stash manages directory skills. The two compose without conflict.

Do I need to restart Claude Code after changing skills?

Yes - the skill list is read once at session start. claude -c resumes the same conversation with the fresh selection.

Install in 30 seconds

macOS out of the box. Linux needs openbsd-netcat for the browser picker.

# get it
git clone https://github.com/grooverLab/stash
cd stash && ./install.sh

# organize the warehouse (preview first)
skills-profile migrate --dry-run
skills-profile migrate

# per project: choose skills, claude launches lean
cd ~/my-trading-project
skills-profile pick
